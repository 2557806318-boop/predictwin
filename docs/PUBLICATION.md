# 公开版内容与脱敏边界

这是全新仓库的框架抽取，不是原工作目录的批量上传。

| 类别 | 处理 |
| --- | --- |
| 检查点调度、HTTPS 连接测量 | 经逐文件检查后保留通用实现 |
| 定点运算、行情窗口、报价、纸盘与审计 | 按公开契约独立封装，移除生产依赖 |
| 实际策略、校准参数、训练模型 | 不发布；策略函数显式留空 |
| 数据库、历史订单、收益、训练样本、回放原始数据 | 不发布；示例全部为合成数据 |
| API Key、私钥、助记词、Telegram 凭据 / 用户标识 | 不发布、不由演示收集 |
| SSH、服务器地址、个人路径、部署备份、日志 | 不发布 |
| 原 Git 分支、提交历史、远程配置 | 不发布；从全新根提交开始 |
| 实盘、钱包签名、资金划转和控制指令 | 不发布 |

公开版不继承原模型的回测结果、运行状态或盈利能力。文档中的图全部为新绘制的抽象架构，不是生产控制台截图。

## 后续发布自检

1. `git status --short`：确认只暂存要公开的源代码、测试和文档。
2. `npm run security:check`：检查路径白名单和常见敏感模式。
3. `git diff --cached`：人工查看全部暂存变更，尤其日志、URL、示例、图片与新依赖。
4. 确保未跟踪 `.env`、数据库、模型、压缩包、备份和密钥文件。
5. 如果未来已经误推凭据，立即撤销 / 轮换，而不只是删除当前文件。Git 历史仍可能保留旧内容。

自动检测仅是辅助，不保证识别所有秘密。新发布的文件、资产和所有历史提交都需要审查。新增二进制图片时，检查截图内容与元数据。
